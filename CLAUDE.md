# Underscore

AI-powered, mood-matched playlists for books being read. See `docs/specs/2026-07-24-underscore-mvp-design.md` (MVP PRD) and `docs/specs/2026-07-24-underscore-api-design.md` (API reference) for the full design.

## Stack

- Monorepo via bun workspaces: `/app` (Expo/React Native), `/server` (Express + TS), `/packages/shared` (zod schemas/types shared across both)
- Postgres + Prisma
- Better Auth for multi-provider login; Spotify integration is a separate connector (app-level client-credentials for catalog search, user-level OAuth for playback only)
- Claude (Anthropic) for mood/genre analysis and track suggestions
- Google Books API for book metadata
- Railway for hosting
- UI: NativeWind 4.2.6 (Tailwind 3.4.17) + react-native-reusables — shadcn/ui proper is web-only. Tokens live in `app/src/global.css`, `app/tailwind.config.js`, `app/src/lib/theme.ts`; gradients are data (`app/src/lib/gradients.ts`) because NativeWind has no gradient classes.
- E2E: Playwright driving the Expo **web** build in Chromium — `playwright.config.ts`, specs in `e2e/`, see `e2e/README.md`. Harness rules (stack isolation, seeding, how specs are written) live in the `e2e-test-writer` agent.

## Working conventions

- "Update the memory file" means update this file, `CLAUDE.md` — not the per-project memory directory.
- Always enter plan mode before starting to make changes and wait for confirmation
- If a plan is confirmed, swich to auto mode
- Always use the `context7-mcp` MCP server before writing code against an external library, framework, SDK, or API — this includes Expo, Better Auth, Prisma, Spotify Web API, the Anthropic SDK, and Google Books, even when the usage seems obvious. Resolve the library id, then query docs scoped to the specific task at hand. Prefer this over relying on training data or web search for library-specific syntax, config, or setup.
- Follow the phased implementation plan in `docs/specs/` — each phase has its own verification steps; don't skip ahead to a later phase's code before the current phase's verification passes. Specs live in `docs/specs/`, not the `docs/superpowers/specs/` that the vendored `brainstorming` skill names; that skill is hash-pinned in `skills-lock.json` and must not be edited to say otherwise.
- Playlists in the MVP are a fixed ~30-track Claude-curated list resolved against Spotify search — no target-runtime/page-count-based sizing and no Spotify Recommendation API usage (deprecated for new Spotify apps as of Nov 2024). Do not reintroduce audio-features-based extension logic.
- Ratings/feedback are out of MVP scope entirely.
- Cut a fresh branch off `main` for each unit of work — don't stack unrelated commits on whatever branch is checked out. Pushing to `origin/main` still needs a confirmation.
- Only commit what the codebase needs to function. Anything reproducible at build or test time — bundles, exports, generated clients, coverage and report output — is ignored, not committed: content-hashed build output replaces its whole tree on every rebuild rather than diffing, so committing it grows history permanently for files nobody reads. `app/dist-e2e/` is the worked example. Never commit an empty file; delete it instead — an empty file is a placeholder someone will later mistake for a real one.
- **Writing or fixing tests is the `e2e-test-writer` agent's job.** When the ask is "write tests", "add e2e coverage", "cover this flow", or "this spec is failing", dispatch that agent rather than writing specs inline — it owns the Playwright conventions and the harness invariants. Two of those invariants bind everyone, not just the agent, because ordinary server work can break them: the test stack is fully isolated from dev (its own ports and its own database — never reuse a dev port or share the dev database), and auth rate limiting stays gated to `NODE_ENV === "production"` in `server/src/lib/auth.ts`. Details in `.claude/agents/e2e-test-writer.md`.
- `.env` files live in the workspace that consumes them — `server/.env`, `server/.env.test`, `app/.env.local` — never at the repo root. Bun resolves `.env` against the process cwd with no parent walk, and `bun run --filter <pkg>` sets cwd to that package, so a root file would be read by nothing while looking authoritative. It also keeps server secrets structurally out of the Expo bundle, where everything reachable is public. `server/.env.test` carries the e2e overrides for running that stack by hand; `webServer.env` in `playwright.config.ts` still wins over it, because Bun's default `.env` loading never overrides a variable already in the process environment.
- The mood vocabulary is closed: `MOODS` in `packages/shared/src/moodProfile.ts` is a ten-value `as const`, `mood` is `z.array(z.enum(MOODS)).max(2)`. Never widen it back to `z.string()` or normalize unknown moods in the UI. To add a mood: edit `MOODS`, add its `MOOD_STOPS` pair in `app/src/lib/gradients.ts`, update Claude's tool schema. It stays closed because each mood needs a gradient standing in for artwork and a chip in the correction UI — an open vocabulary would render as an unstyled hole in the UI.
- HTTP goes through axios on both sides — the server's outbound calls to Google Books, Spotify and Anthropic (`server/src/connectors/*`, built on the `createHttpClient` factory in `server/src/lib/http.ts`), and the app's calls to our own API (`app/src/lib/api-client.ts`). Server-state fetching in the app goes through TanStack Query (`@tanstack/react-query`): one hook module per endpoint under `app/src/features/<domain>/`, never a bare `useEffect` fetch. React Query is a client cache and has no place in the server.
- **The design lives in the Claude Design MCP and nowhere else.** Fetch it with the `DesignSync` tool (`list_files`, then `get_file`) against project `472ebb80-2946-470b-9e65-06b8032cf833`, authorising via `/design-login` if a call returns an authorization error. There is deliberately **no local copy** — the `docs/design/` mirror was deleted because a snapshot records when it was last pulled and then goes stale silently. Don't recreate one; `docs/design/` stays in `.gitignore` so a stray pull can't be committed.
- **To check the app against the design, dispatch the `design-handoff-sync` agent** (`.claude/agents/design-handoff-sync.md`) rather than fetching by hand — it pulls the design fresh from Claude Design every run, and knows the precedence rules and which deviations are deliberate. It reports; it doesn't implement.
- **The live design is the `.dc.html` files at the MCP project root** — `Under Score App.dc.html` and its siblings. That is what the designer edits, and it is the only thing to build from. The `design_handoff_under_score_app/` subtree is a **point-in-time export and goes stale**: on 2026-09-03 its prototype was three revisions behind the root file, and book detail was built twice against it before that surfaced. Don't read it, and don't treat its `README.md` as the spec — the prose describes whichever export it shipped with, so where it disagrees with the root prototype it is simply out of date. Precedence runs root prototype → `_ds/…/_ds_bundle.js`: the prototype shows what the *screens* are, the bundle what the *components* are, and where a screen inlines its own version instead of using the DS component, the screen wins. The prototypes are references to recreate, not code to port. The app follows the device colour scheme, so every surface needs both themes built; neither is a default.
- **Re-fetch the design at the start of any UI work, and again before calling it done** — it moves mid-task. `get_file` on the root prototype is ~74 KB and the tool spills that to a file path rather than into context, so diff it against the previous pull with `diff` instead of re-reading it by eye.
- The splash's `us-fall` transition (the record growing to cover the viewport, `app/src/app/splash.tsx` + `splash-backdrop.tsx`) is **kept deliberately** even though the second handoff dropped its spec — that removal was read as the doc shedding rationale prose, confirmed with the designer. Don't delete it as dead spec on a future read. The same handoff's "Splash gradient (revised)" section is already satisfied by `splash-backdrop.tsx`'s record-concentric radial fade; its `blur(30px)` stays unimplemented for the reason documented in that file.
- **Once a feature works, do a comment pass before calling it done.** Delete every comment that restates what the code already says — the code is the description of itself, and a second copy in prose only rots out of sync with the first. Rewrite instead of annotate: a named constant, a split function or a clearer variable removes the need for the comment rather than justifying it. What survives the pass is the part the code genuinely cannot say — why a design call went the way it did, what the rejected alternative was, a constraint that lives in another system. Prefer that on the module or function, not scattered per line. Comments written while building are cheap and expected; leaving them all in is what this rule is against.
- Run `bun run typecheck` and `bun run lint` from the root (they fan out across workspaces) before calling work done; `bun run test:e2e` for the Playwright suite.
